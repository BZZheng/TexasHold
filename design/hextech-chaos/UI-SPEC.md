# 海克斯大乱德 UI 与交互契约 v0

本文件和同目录的 `prototype.html` 共同构成开发输入。它们不是气氛参考。实现若与本文件冲突，以“不遮挡牌面、服务端权威、移动端可完成操作”为优先级。

## 1. 交付范围

- 海克斯房间创建与模式摘要
- 等待房间人物选择
- 每手技能三选一
- 牌局外 30 项公共技能图鉴，可从大厅、海克斯创建页和等待房预习
- 牌局人物 HUD 与公共装备
- 指定目标技能
- 观战手牌切换
- 人物成长与觉醒
- 动态胜利目标、贷款净资产与手数进度
- 320、375、414、768、960 和桌面宽度

## 2. 强制布局分区

牌局主列必须使用正常文档流或 CSS Grid，按以下顺序建立三个互不重叠的轨道：

1. `table-zone`：椭圆牌桌、座位、底池和公共牌。
2. `hand-rail`：自己的手牌或当前观战玩家手牌。
3. `control-rail`：下注按钮、人物技能、公共装备和三选一卡组。

禁止让 `control-rail` 使用固定定位覆盖 `hand-rail`。禁止让任何技能面板、结果面板或人物详情进入公共牌安全区。

### 2.1 公共牌安全区

- 位于椭圆牌桌几何中心。
- 宽度至少容纳五张牌和四个间距。
- 公共牌出现后，底池文字移动到公共牌上方，街道文字位于下方。
- 技能提示使用顶部 `event-lane`，不能放在公共牌上。
- 目标选择只改变座位外框，不增加牌桌中央弹窗。
- 觉醒提示不能覆盖公共牌。

### 2.2 手牌轨道

- 玩家视角显示自己的两张底牌。
- 弃牌后的本局观战视角显示状态说明，不显示其他玩家手牌，除非观战规则明确授权。
- 授权观战时，轨道标题必须显示“正在观看 {玩家名}”。
- 切换观战玩家只替换轨道内容，不弹出浮层。
- 任何状态下，三选一卡组不能进入手牌轨道。

### 2.3 操作轨道

- `skill_select` 阶段：显示三选一，下注按钮尚未出现。
- 正常牌局：显示人物 HUD、四个下注动作和已装备技能。
- `target_select` 阶段：下注动作替换为目标说明与取消按钮，牌桌和手牌不变化。
- `spectator` 阶段：显示切换视角按钮。
- `awaken` 详情：只替换操作轨道内容，不创建覆盖牌桌的模态框。

## 3. 响应式合同

### 3.1 桌面，宽度至少 960 px

- 页面为牌桌主列与 290-320 px 侧栏。
- 主列三个轨道最小高度建议：牌桌 330 px、手牌 110 px、操作 190 px。
- 侧栏包含玩家、技能图鉴、记录和动态目标。

### 3.2 平板，768-959 px

- 侧栏改为抽屉。
- 主列仍保持三个轨道。
- 三选一卡组可以保持三张横排。

### 3.3 手机，320-767 px

- 顶栏高度约 50 px，事件轨道约 30 px。
- 侧栏完全移入抽屉。
- 牌桌建议占剩余页面的 42%-48%，但不得低于 260 px。
- 手牌轨道 96-110 px。
- 操作轨道 190-220 px。
- 三张技能卡必须同屏，不依赖横向滚动才能看到第三张。
- 手机卡面可以省略长描述，但必须保留类别、名称和插画。
- 所有触摸目标至少 44 x 44 px；原型中的极小按钮在正式实现时需要扩大点击热区。
- 320 px 下不得横向滚动。

## 4. 房间与人物选择状态机

```text
create_room
  -> waiting_for_players
  -> character_select
  -> character_locked
  -> ready
  -> host_start
```

- 人物卡显示：头像、名称、定位、被动、主动、成长条件、觉醒。
- 卡片第一次点击为预览，点击主按钮才确认。
- 玩家准备后人物锁定。
- 人物被其他玩家选择后置灰并显示占用者。
- 取消准备后可以更换人物，但不能抢占已锁人物。
- 房主开始前，所有玩家必须选择人物并准备。

## 5. 每手技能状态机

```text
deal_hole_cards
  -> skill_select (60s)
  -> skill_locked
  -> preflop_action
  -> optional_skill_armed
  -> optional_target_select
  -> skill_resolve
  -> betting_action
```

- 三个选项由服务端发送，前端不能自行重抽或推导概率。
- 预选不会提交。
- 点击“装备 {技能名}”才提交。
- 超时由服务端选定，并返回 `autoSelected: true`。
- 技能冷却由服务端返回，前端只显示。
- 金色海克斯最多一张，发放约束由服务端执行。
- 本场一次免费刷新需要单独确认，刷新后旧选项永久失效。
- 60 秒选择窗只承担当手取舍；完整技能规则必须在发牌前通过牌局外图鉴访问。图鉴按共享规则展示类型、时机、目标、代价、风险、反制与操作步骤，关闭后保留来源页面状态。

## 6. 目标选择

- 可选目标来自服务端的 `validTargetUserIds`。
- 前端不得根据本地状态自行开放额外目标。
- 有效座位显示金色外框和“选择”。
- 无效座位置灰，仍显示其筹码和人物资源。
- 点击目标后先显示风险摘要；零成本且无不可逆影响的技能可以直接提交。
- 魅惑、缴械、贷款等涉及筹码或不可逆状态时必须二次确认。
- 取消后回到原操作状态，行动倒计时是否暂停由具体技能规则决定。

## 7. 人物 HUD

自己的 HUD 包含：

- 人物头像与名称
- 可公开资源，例如胆识 3/3
- 成长进度
- 主动技能状态：可发动、条件不足、冷却、已用尽
- 觉醒状态

其他座位只展示服务端允许公开的资源，不展示秘密装备、隐藏进度或窥牌结果。

## 8. 觉醒交互

- 觉醒发生时顶部事件轨道显示一句结果。
- 人物头像边框进行不超过 420 ms 的变化。
- 操作轨道在当前无行动需求时可以显示完整觉醒说明。
- 若当前正轮到玩家下注，只显示紧凑提示，不替换下注按钮。
- 详情可稍后从人物 HUD 打开。
- 减少动态模式下禁用头像形变，只更新插画、名称和状态。

## 9. 观战

- 公共牌始终处于牌桌安全区。
- 当前允许查看的手牌始终处于 `hand-rail`。
- 玩家切换器处于 `control-rail` 或侧栏。
- 神秘玩家、私人玩家和已弃牌不可查看状态必须由服务端返回。
- 不允许通过 DOM 隐藏但仍下发数据的方式保护手牌。
- 视角切换失败时，保留原手牌，不显示空白闪烁。

## 11. 动效

- 卡牌预选：180 ms，`transform` 与 `opacity`。
- 卡组进入：220 ms，三张牌依次间隔 40 ms。
- 技能锁定：卡面下压并盖章，220 ms。
- 目标高亮：不循环闪烁，只显示稳定外框。
- 觉醒：最长 420 ms。
- 所有动效支持 `prefers-reduced-motion`。

## 12. 可访问性

- 卡片选择使用按钮或 `role=listbox/option`，并提供 `aria-selected`。
- 颜色不能作为稀有度、作弊状态和可用状态的唯一提示。
- 倒计时使用 `aria-live` 低频播报，不逐秒打断读屏。
- 目标选择支持键盘顺序与 Escape 取消。
- 卡面长描述必须能通过详情按钮阅读，不能只依赖悬停。
- 文字与背景满足 WCAG AA。

## 13. 开发验收

- [ ] 320、375、414、768、960、1440 px 无横向滚动。
- [ ] 五张公共牌在所有技能状态下完整可见。
- [ ] 自己的两张手牌在技能选择和目标选择状态下完整可见。
- [ ] 授权观战手牌在切换技能或人物详情时完整可见。
- [ ] 三张技能卡在 320 px 同屏可辨认。
- [ ] 目标选择不创建牌桌中央弹层。
- [ ] 轮到玩家下注时，觉醒说明不替换操作按钮。
- [ ] 减少动态偏好生效。
- [ ] 服务端未授权的手牌不会进入浏览器状态。

## 14. v0 限制

- 当前只有粉香、剑圣哥、资哥三张示例立绘。
- 其余人物暂用文字占位，不代表最终资产。
- 技能卡使用汉字印章占位，最终需要独立透明背景技能贴纸。
- v0 用于确认信息架构、布局和双层视觉，不用于确认所有最终插画细节。

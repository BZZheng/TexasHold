# TexasHold 热状态与外部归档设计

## 目标

- 牌局计算、发牌、行动校验、WebSocket 响应和恢复快照都在应用主机完成。
- 玩家操作的关键路径不访问外部归档端；归档端或私有网络暂时不可用时，正在进行的牌局仍可继续。
- 应用主机只保留恢复牌局所需的热数据和有容量上限的待归档队列。
- 完整历史、长期快照和结构化日志由独立归档端保存。
- 仓库只描述通用拓扑和配置键，不记录任何实际主机、地址、地域、账号或挂载路径。

## 部署拓扑

```text
玩家浏览器
    │ HTTPS / WebSocket
    ▼
应用服务
    ├── 内存：当前牌局计算
    ├── $DATA_DIR：热状态 + 有界归档队列
    └── 受限导出命令
                     ▲
                     │ 私有网络上的异步拉取
                     │ 限权 SSH
                     │
外部归档端
    ├── 完整牌局历史
    ├── 快照与校验清单
    └── 结构化应用日志
```

不要把 SMB/NFS 等网络文件系统直接作为在线状态目录。Node.js 的同步 JSON 原子写入和未来可能采用的嵌入式数据库，都不应把网络抖动放进牌局关键路径。

## 当前数据模型

当前版本没有外部数据库，不需要数据库服务器、连接 URL、数据库账号或建库建表步骤。服务端在 `DATA_DIR` 中维护以下 JSON 状态；这些都是运行数据，不得进入 Git：

```text
$DATA_DIR/
├── hot/
│   ├── texashold.json          # 账号、会话摘要、当前积分
│   └── runtime-rooms.json      # 可恢复的进行中牌局
├── archive-ring/               # 有界历史事件
├── logs/                       # 有界结构化日志
└── replication-state.json      # 外部归档确认游标
```

测试通过系统临时目录创建隔离状态并在结束后删除。若未来引入关系型数据库，公开仓库仅保留可复现的 `database/schema/**/*.sql` 和不含真实用户信息的 fixture；任何连接参数与转储文件仍必须留在仓库外。

## 数据分层

| 数据 | 应用主机 | 外部归档端 | 同步策略 |
| --- | --- | --- | --- |
| 当前房间、牌堆、手牌、筹码、行动令牌 | 热数据权威副本 | 恢复快照 | 每次状态变更原子写入；后台拉取 |
| 账号、密码哈希、有效会话摘要 | 登录所需热副本 | 受保护的恢复快照 | 变更后进入下一批快照 |
| 当前积分与排行榜 | 热副本 | 结算事件归档 | 玩家结算后异步归档 |
| 完整牌局历史 | 有界缓存 | 长期归档 | 按事件 ID 去重拉取 |
| 应用日志 | 热文件与有界归档环 | 按日归档 | 轮转后校验哈希并拉取 |

密码哈希、会话摘要、牌堆、底牌和进行中房间即使不是明文凭据，也必须始终按敏感数据处理。

## 容量与失败策略

- `hot/` 超过配置上限时拒绝创建新房间并告警，但不破坏进行中牌局。
- `archive-ring/` 超过上限后，仅回收已被外部归档确认且超过热缓存窗口的最旧内容。
- 日志使用按文件大小、时间和总容量限制的归档环；日志或归档端不可用不会反压玩家操作。
- 磁盘空间低于安全阈值时停止非关键写入和新房间创建，正在进行的牌局继续。
- 每批归档先写临时文件，验证 JSON 与 SHA-256 后再原子改名；重复内容按 ID 或内容哈希去重。

## 写入与同步时序

1. 服务端校验行动令牌、玩家身份、筹码和牌局阶段。
2. 在内存中完成状态变化。
3. 原子写入 `runtime-rooms.json`。
4. 立即通过 WebSocket 返回新状态。
5. 一手牌结束时，将结算事件追加到本地有界归档环。
6. 外部归档任务在后台拉取并按事件 ID 去重保存。

外部归档不参与前四步，因此网络延迟不会叠加到过牌、跟注、加注、弃牌或发公共牌的响应时间中。

## 安全边界

- 归档端主动拉取，应用主机不主动连接家庭或办公网络。
- 使用独立 SSH 密钥，并在 `authorized_keys` 中配置固定命令、来源限制、禁止 PTY 和端口转发。
- 导出包不包含明文密码或可直接复用的会话令牌。
- 真实远端、用户名、密钥和目录只通过被 Git 忽略的环境文件提供。
- 数据目录权限为 `0700`，数据文件权限为 `0600`。
- 未鉴权健康接口不得返回实际数据目录、远端地址或连接配置。

## 验收标准

- 暂停外部归档后，多人牌局仍可正常行动和结算。
- 恢复归档后，积压事件按 ID 补齐且没有重复记录。
- 连续加注、全押和发牌时，响应时间与关闭归档任务时相比无明显退化。
- 重启应用后，正在进行的牌局能够从最近一次本地原子快照恢复。
- 从经过校验的归档快照在空目录恢复后，账号、积分、房间和进行中牌局一致。
- 应用数据超过配置阈值时触发保护，且不会删除尚未确认归档的数据。
